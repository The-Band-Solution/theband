Divergence Row

An issue whose declared type and structure disagree is flagged in its own row on /work. Today the row says only what kind of divergence it is. Which side the platform followed is written once, in the summary card, per kind. This proposal puts the declared type, the derived concept, the reason they diverge and the side the platform followed into the row itself. Labels stay in their own column as context.

Decided 2026-09-30 · maintainer · as proposed by DesignD4. The divergence block lives inside “promoted to”, and labels never enter it. The card’s empty state says “Declared type and structure agree”. The followed side is drawn with a solid underline and the other side with a dotted one.
Q1 · Decided 2026-09-30 · maintainer · (a)Does the row carry a “why” line that names the structure?

For user_story_without_parts, “Feature” routes to atomic user story, which is exactly the verdict. The two sides name the same concept. What disagrees is the declared intent and the empty structure. Without a reason, “Feature · atomic user story · diverges” reads as a contradiction that does not exist.

  • (a) yes: one line, “why: …”, from the kind
  • (b) no: claim, verdict and the diverges mark only

Recommendation: (a). It is the only line that tells the reader what to fix (decompose it, or link the tasks).

Q2 · Decided 2026-09-30 · maintainer · (a)Where does the block live?
  • (a) inside the “promoted to” cell, under the evidence mark
  • (b) a full-width line under the row
  • (c) a new “divergence” column

Recommendation: (a). The table keeps its eight columns and the shared table component stays as it is. When stacked on a phone, the block stays under its own label. Option (b) would need a second row type in the component, and (c) adds a column that is empty on 4 918 of 5 629 rows.

Q3 · Decided 2026-09-30 · maintainer · (a); the empty declared_concept becomes its own bugThe claim is the type as written at the source, because declared_concept is never recorded.

In the development database declared_concept is empty on all 711 divergences, although github_issue_type_routing.yaml says to record it. The row can show only issue_type (“Feature”).

  • (a) show the type as written now, and file the missing declared_concept as a defect for the Product Owner
  • (b) hold the row until declared_concept is recorded, then show the concept the type routes to

Recommendation: (a). The type as written is the team’s own claim and is observed. Recording the concept is a separate fix and does not change this layout.
