# v0.12.0 — nine security fixes that are in `development` and not in production

> **Why now.** Measured on 2026-10-02: production answers `0.11.0` on `/version`, and
> `development` carries nine security fixes merged between 2026-10-01 and 2026-10-02. The house
> rule (AGENTS.md §14.0) sends a security fix in the **first possible release**, without waiting for
> the next feature. Spec 070 (the platform operator) is **not** in this release: its stack (#1132 to
> #1138) has not been merged yet.

**Release from `development` to `main`.** Merge commit, never squash (L83). Afterwards, a
**back-merge** through a `back-merge/v0.12.0` branch created from `origin/main`, never with `main` as
head (#998).

**Proposed on 2026-10-02**, without the `product-owner` agent: the assessment was done by whoever
prepared the release, with the measurements of steps 2 and 3 of the `release` skill, and that is
stated here. **The moment of delivery belongs to the maintainer.**

## The security fixes

| PR | what it closes |
|---|---|
| #1039 | `Access.operacional?/2` now compares the account's tenant **before** granting admin reach. Before, an admin account of one tenant could pass the check on a resource of another |
| #1040 | `ApiTokens.criar/4` refuses an owner or author from **another tenant** |
| #1038 | a suspended tenant is not collected, not reprocessed and does not go to the model |
| #1048 | the login's growing wait can no longer be bypassed with parallel attempts (`FOR UPDATE` on the account) |
| #1049 | the refusal by wait pays the cost of the hash, and the response time no longer reveals whether the e-mail exists |
| #1044 | an already open screen falls when its session is ended: disabling the account, the password being set by another person, signing out in another tab |
| #1051 | the operational rotation of sessions runs through the serving node (`rpc`) and drops open screens; runbook §10.2 gives the command |
| #1053 | the master key rotation re-encrypts **all** encrypted fields, including the AI provider's credential, and now exists in production (`TheBand.Release.rotacionar_chave/0`, runbook §12) |
| #1130 | a tenant is never left without an active administrator: disabling the last one is refused, with a lock against two disablements in parallel |

## What else goes

| PR | what it is |
|---|---|
| #1036, #1029, #1032 | `/syncs` says when the queue stopped and disables **Sync** and **Reprocess** with the reason; the health of the queue is read by `/health` and by the container's healthcheck; the Cron jobs get their own queue (#801) |
| #1045 | searching in `/people` in a tenant without people no longer brings the screen down |
| #1028 | the old session token column is no longer written or read (064/T014a). **No migration**: the column stays, and goes away in a future release |
| #1043 | test only |
| #905, #1054 | documentation only (the 065 amendment and the 070 specification) |

## What users will notice

| what | for whom |
|---|---|
| `/syncs` shows that the queue stopped, and the Sync and Reprocess buttons are disabled with the reason | whoever operates the collection |
| an open screen goes to `/sign-in` when the session is ended by another path | all accounts |
| disabling the **last** active administrator is refused on the accounts screen, with the sentence giving the reason | whoever administers |
| several sign-in attempts in parallel wait like attempts in series | nobody who signs in normally |

## The version, and why

**v0.12.0, MINOR.** #1036 delivers new capability on the screen (`/syncs` saying that the queue
stopped, and `/health` reading the queue), without breaking a contract. The security fixes alone
would be PATCH; in a release that carries MINOR, they do not raise the number.

## The gap this release declares

**None of the PRs above has a recorded review** (`gh pr view <n> --json reviews` gives an empty list
for #1036, #1038, #1039, #1040, #1044, #1048, #1049, #1051, #1053 and #1130). The gates passed on
each one, and the gates are not review (principle VII, L95). The decision to ship security fixes
without a recorded independent review, or to wait for it, belongs to the maintainer.
