### D. Write method: the order between 401 and 405

```bash
for M in POST PUT PATCH DELETE; do
  curl -s -o $S/d_$M.b -w "$M HTTP %{http_code}  " -X $M "$PRODUCAO_URL/api/v1/teams"; cat $S/d_$M.b; echo
done
curl -s -o $S/d.b -w "POST com Bearer inventado HTTP %{http_code}\n" -X POST -H "Authorization: Bearer $FAKE" "$PRODUCAO_URL/api/v1/teams"
curl -s -I -w "HEAD HTTP %{http_code}\n" "$PRODUCAO_URL/api/v1/teams"
```
```
POST   HTTP 401  {"error":{"code":"unauthorized","message":"The credential presented is not usable.","request_id":"GNhGm-LYG0E6SwEAAAWh"}}
PUT    HTTP 401  {"error":{"code":"unauthorized",…,"request_id":"GNhGm_lQ7hg6SwEAAAXB"}}
PATCH  HTTP 401  {"error":{"code":"unauthorized",…,"request_id":"GNhGnA3Ydh46SwEAAAXh"}}
DELETE HTTP 401  {"error":{"code":"unauthorized",…,"request_id":"GNhGnCJ6s0g6SwEAAAYB"}}
POST com Bearer inventado HTTP 401
HEAD   HTTP 401  (content-type: application/json)
```

**Observed order**: without a valid credential, the 401 comes before the 405. It is so by construction:
in the v0.9.1 router, `scope "/api/v1"` does `pipe_through [:api, :api_autenticada]`, and the
`match :*, …, :nao_permitido` only runs after authentication.

**What the spec promises**: it does not define the precedence. SC-006 says *"0 methods other than `GET`
and `HEAD` respond on `/api/v1`"*. The `erro.md` contract says 405 for *"any method other
than `GET` and `HEAD`"*. Quickstart §7 measures the 405 **with** `Authorization: Bearer $TOKEN`.
None of the three asks for 405 for someone arriving without a credential. So the observed order does not
contradict the spec, and the "does not respond" of SC-006 holds for whoever arrives anonymous: no
write was served. The 405 code itself can only be measured with a valid token.

## Findings

1. **A nonexistent path under `/api/v1` answers with the site's HTML page, and not with the
   single error format.** It may be an implementation defect (cause 2) or a spec gap
   (cause 3). The PO decides.
   ```bash
   curl -s -o $S/nx.b -w "HTTP %{http_code} ct=%{content_type}\n" "$PRODUCAO_URL/api/v1/nao-existe"
   curl -s -o $S/nx2.b -w "HTTP %{http_code}\n" -X POST "$PRODUCAO_URL/api/v1/nao-existe"
   ```
   ```
   GET  /api/v1/nao-existe  HTTP 404 ct=text/html; charset=utf-8   <!DOCTYPE html>… <title>TheBand · The Band
   POST /api/v1/nao-existe  HTTP 404                               <!DOCTYPE html>…
   ```
   FR-020 says *"a single format for all codes"*, and the contract lists `404
   not_found` in JSON. A client that wrote "one handler, not six" (`erro.md`) receives
   HTML and breaks on parsing instead of reading `error.code`. **What an integrator would see**: an
   invalid-JSON error, without `request_id`, in place of `not_found`. The router comment
   deliberately refuses the catch-all that would give 405 (*"the inverse lie"*), but nothing in the
   router nor in the tests under `test/the_band_web/api` covers the nonexistent path. The
   401/404 distinction without a credential leaks nothing: the 8 routes are published in the anonymous
   OpenAPI description.

2. **Without a credential, the 401 comes before the 405** (item D). The spec does not say which comes first.
   The behavior is defensible: it confirms nothing to someone who has not identified themselves. It is worth writing the
   order down in the `erro.md` contract, so that nobody treats the order as a defect later.

3. **Whether "Copy value" works cannot be verified in production without writing there.** To
   see the button one has to generate a token. By the rule of the check, this is a finding about the
   criterion, and not an authorization to generate one. Even with a test account, this item stays
   out, unless another source of evidence is decided (for example, checking only the served
   JS, as item B does).

4. **(local, outside production)** The local `main` ref of this checkout is stale (`mix.exs`
   `0.2.0`), while `origin/main` is at `0.9.1`. It does not affect production. It only misleads whoever
   compares versions against `main` without `origin/`.

Classification: nothing here is "the release did not go up" (cause 1). The version live is the expected one, and
the state of "Copy value" is the inherited one, already recorded.
